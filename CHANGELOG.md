# Журнал изменений проекта

Формат записей основан на принципах Keep a Changelog.
Версии соответствуют сборкам, описанным в плане практики.

## [0.1.0] — 2-й день практики

### Добавлено

**Инфраструктура проекта**
* Репозиторий Git инициализирован, настроен файл `.gitignore`.
* Файл `package.json` с описанием проекта, перечнем зависимостей и сценариями запуска.
* Файл `.env.example` — образец настроек окружения (порт, путь к БД, уровень логирования).
* Файл `pnpm-workspace.yaml` с настройкой `nodeLinker: hoisted` для корректной
  работы `node_modules` в Windows.

**Подключение базы данных SQLite**
* `src/db/connection.js` — единое соединение с БД (паттерн Singleton), PRAGMA
  `foreign_keys`, `journal_mode = WAL`, `busy_timeout`, функция `ping()` для проверки
  доступности, вспомогательная функция `transaction()`.
* `src/db/migrate.js` — собственный механизм миграций с учётом применённых
  скриптов в таблице `schema_migrations`; каждая миграция выполняется в транзакции.
* `src/db/migrations/001_initial_schema.sql` — схема базы данных, спроектированная
  на 1-й день: таблицы `Users`, `Orders`, `Storage_Cells`, четыре индекса, частичный
  уникальный индекс активной ячейки, триггер освобождения ячейки и 20 стартовых ячеек.

**Каркас сервера**
* `src/config/index.js` — централизованное чтение конфигурации с проверкой типов.
* `src/utils/logger.js` — логгер с уровнями `error`/`warn`/`info`/`debug`.
* `src/utils/AppError.js` — класс прикладной ошибки с HTTP-статусом и статическими
  фабриками (`badRequest`, `unauthorized`, `forbidden`, `notFound`, `conflict`,
  `unavailable`).
* `src/middleware/requestLogger.js` — журналирование запросов с длительностью обработки.
* `src/middleware/errorHandler.js` — обработчики 404 и централизованный обработчик
  ошибок, единый JSON-формат ответа об ошибке.
* `src/routes/health.js` — эндпоинты `/health`, `/health/live`, `/health/ready`.
* `src/app.js` — сборка приложения Express: разбор JSON, логирование, заголовки
  безопасности, статика, корневой маршрут, заготовка префикса `/api`.
* `src/server.js` — точка входа: подготовка БД, применение миграций, запуск
  HTTP-сервера, корректная остановка по `SIGINT`/`SIGTERM`, обработка
  `uncaughtException` и `unhandledRejection`.

**Вспомогательные сценарии**
* `scripts/setup.js` — первоначальная настройка проекта: проверка версии Node.js,
  создание файла `.env`, проверка зависимостей, создание базы данных, применение
  миграций и контрольная проверка сборки (команда `npm run setup`).
* `scripts/migrate.js` — применение миграций и вывод их состояния (`status`).
* `scripts/reset-db.js` — полное пересоздание базы данных с подтверждением.
* `scripts/check-v0.1.js` — автоматическая проверка сборки по 11 контрольным точкам.
* `scripts/archive-day.js` — создание снимка исходного кода в архив дня практики.

**Тестирование**
* `tests/smoke.test.js` — 4 модульных теста каркаса на встроенном модуле `node:test`.

**Документация**
* `README.md` — назначение, стек, структура, инструкция по установке и запуску,
  описание эндпоинтов, схемы БД и настроек.
* `CHANGELOG.md` — журнал изменений по дням практики.
* Отчёт о работе за день в формате DOCX с титульным листом
  (`Разработка\день 2\Отчет_день_2_каркас_сервера_и_SQLite.docx`).

### Технические решения

* Выбрана библиотека `better-sqlite3`, а не `node:sqlite`: она предоставляет
  синхронный API и готовые бинарные сборки (N-API prebuilds), поэтому установка
  не требует компилятора C++ и работает на Node.js 20 и выше.
* Механизм миграций написан самостоятельно вместо подключения ORM: весь SQL
  остаётся видимым и проверяемым, что важно для защиты учебного проекта.
* Логгер и middleware журналирования реализованы без сторонних библиотек
  (`morgan`, `winston`) — меньше зависимостей, полный контроль над форматом вывода.

## [0.0.1] — 1-й день практики

### Добавлено

* Проектирование архитектуры базы данных: три связанные таблицы `Users`,
  `Orders`, `Storage_Cells`.
* SQL-скрипт `schema.sql`, создающий базу данных без ошибок (проверен
  выполнением в SQLite).
* Ограничения целостности: внешние ключи, `CHECK`-условия на значения
  перечислений, частичный уникальный индекс на активную ячейку, триггер
  автоматического освобождения ячейки.
