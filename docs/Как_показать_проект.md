# Как показать проект преподавателю

Краткая инструкция: что запустить, что показать и что говорить.

---

## 1. Запуск за одну команду

Открой терминал в папке проекта и выполни:

```bash
cd "Практика 2026\pvh-service"
npm run demo
```

Всё остальное сценарий сделает сам:

* проверит файл настроек `.env`;
* применит миграции к базе данных;
* создаст учётную запись администратора и 20 ячеек хранения;
* запустит перехватчик писем;
* запустит сервер;
* откроет в браузере сайт и панель с письмами.

Через 10–15 секунд в консоли появится:

```
================== ПРОЕКТ ГОТОВ К ПОКАЗУ ==================
Сайт:                 http://127.0.0.1:3000
Эндпоинт проверки:    http://127.0.0.1:3000/health
Письма (перехватчик): http://127.0.0.1:8025
Учётная запись администратора:
  адрес:  admin@pvh.local
  пароль: Admin#2026Pvh
===========================================================
```

**Это окно терминала не закрывай** — в нём работает сервер.

## 2. Что открыть в браузере

| Вкладка | Адрес | Что показывает |
|---|---|---|
| Сайт | http://127.0.0.1:3000 | само приложение |
| Почта | http://127.0.0.1:8025 | ящик, куда приходят письма |
| Проверка сборки | http://127.0.0.1:3000/health | состояние сервера и базы данных |

Расставь их в браузере рядом — так удобнее показывать: зарегистрировался
на сайте, тут же видно письмо в ящике.

---

## 3. Порядок показа (7–10 минут)

### Шаг 1. Сервер работает

Открой http://127.0.0.1:3000/health и покажи ответ:

```json
{
  "status": "OK",
  "version": "0.9.0",
  "database": {
    "engine": "SQLite",
    "connected": true,
    "tables": ["Orders", "Sessions", "Storage_Cells", "Users", "schema_migrations"]
  }
}
```

> **Что сказать:** сервер запущен, соединение с базой данных установлено,
> схема применена — пять таблиц.

### Шаг 2. Регистрация

Открой http://127.0.0.1:3000/register и заполни форму:

| Поле | Значение |
|---|---|
| Имя | Иванов Иван |
| Адрес электронной почты | ivanov@mail.ru |
| Пароль | Parol12345 |
| Подтверждение пароля | Parol12345 |

**Покажи специально ошибки** — это вызовет доверие:

* введи пароль `parol` — появится «Пароль должен содержать не менее 8 символов»;
* введи адрес `ivanov@mail` — появится «Укажите корректный адрес
  электронной почты»;
* убери галочку согласия — появится соответствующее требование;
* обрати внимание, как индикатор под полем пароля меняет цвет
  и показывает оценку надёжности.

Исправь значения и нажми **Зарегистрироваться**.

> **Что сказать:** проверка идёт в двух местах — в браузере для удобства
> и на сервере для защиты. Правила одинаковые, поэтому обойти проверку
> нельзя.

### Шаг 3. Письмо пришло

Перейди на вкладку http://127.0.0.1:8025 — **в ящике появилось письмо**.

Открой его и покажи:

* тему: «Подтверждение адреса электронной почты — Сервис ПВЗ»;
* что есть и текстовая, и HTML-версия письма;
* **ссылку для подтверждения**.

> **Что сказать:** письмо отправлено по протоколу SMTP собственным
> клиентом, написанным на встроенных модулях Node.js — сторонние
> библиотеки не использовались. Письмо содержит две версии: обычный текст
> и HTML, тема закодирована по стандарту RFC 2047.
>
> Ящик локальный, поэтому письмо не уходит в интернет — это удобно
> для проверки: видно, что отправка действительно работает.

### Шаг 4. Вход запрещён до подтверждения

Вернись на сайт, открой http://127.0.0.1:3000/login и попробуй войти
с теми же данными.

Появится предупреждение «Адрес электронной почты не подтверждён»
и кнопка отправки письма повторно.

> **Что сказать:** это требование технического задания — вход разрешён
> только пользователям с подтверждённым адресом.

### Шаг 5. Подтверждение адреса

Вернись в письмо (http://127.0.0.1:8025) и **нажми на ссылку** в нём.

Откроется страница «Адрес электронной почты подтверждён».

Покажи, что ссылка одноразовая: нажми её ещё раз — появится
«Ссылка недействительна» с предложением запросить новое письмо.

> **Что сказать:** токен подтверждения действует 24 часа и срабатывает
> один раз. Повторное использование ссылки не активирует учётную запись.

### Шаг 6. Вход выполнен

Вернись на http://127.0.0.1:3000/login и войди.

Обрати внимание:

* в шапке появилось имя пользователя и кнопка **Выйти**;
* вместо ссылок «Войти» и «Регистрация» — имя и роль;
* страница приветствует пользователя по имени.

> **Что сказать:** сессия хранится в базе данных, а в браузер отдаётся
> только токен в защищённой cookie. В базе хранится не сам токен,
> а его хеш — если база окажется в чужих руках, воспользоваться
> сессией не получится.

### Шаг 7. Разграничение прав

Самое наглядное для проверки требований:

1. Войди как **клиент** (`ivanov@mail.ru`) и перейди на
   http://127.0.0.1:3000/api/admin/overview
2. Увидишь **403 Forbidden** — «Недостаточно прав для выполнения операции»
3. Выйди и войди как **администратор**: `admin@pvh.local` / `Admin#2026Pvh`
4. Открой тот же адрес — увидишь сводку по пункту выдачи

> **Что сказать:** в системе две роли — клиент и администратор. Права
> проверяются на сервере, а не скрытием кнопок в интерфейсе. Клиент
> получает отказ 403 при обращении к административным разделам.

### Шаг 8. Адаптивность и тема оформления

* Сузь окно браузера до половины экрана — меню свернётся в кнопку,
  сетки перестроятся в одну колонку.
* Нажми кнопку с луной в правом верхнем углу — включится тёмная тема.
* Обнови страницу — тема сохранится.

> **Что сказать:** вёрстка адаптивная, рассчитана на компьютеры, планшеты
> и телефоны. Выбор темы сохраняется в браузере.

## 4. Автоматическая проверка (если попросят доказательства)

Это самая сильная часть показа. Выполни в отдельном окне терминала:

```bash
npm test
```

Результат: **257 тестов в 15 файлах, все пройдены**.

```bash
npm run check
```

Результат: **61 проверка, все пройдены** — сценарий сам поднимает сервер
и проверяет всю цепочку от регистрации до выхода из системы.

```bash
npm run check:v01    # проверка первого дня практики
npm run check:v09    # и так по всем дням
```

> **Что сказать:** по каждому дню практики есть отдельный сценарий
> автоматической проверки. Они сохранены все — видно, как проект
> развивался от запуска сервера до полноценной авторизации.

## 5. Что показать в коде

Коротко пройди по структуре проекта в редакторе:

```
src/
├── config/index.js         настройки и их проверка
├── db/migrations/          миграции базы данных (4 файла)
├── repositories/           запросы к базе данных
├── services/               бизнес-логика
├── routes/                 обработка HTTP-запросов
├── middleware/             проверка прав доступа, cookie, ограничение частоты
├── validators/             правила проверки полей
├── mail/                   SMTP-клиент и шаблоны писем
└── views/                  шаблоны страниц
```

Что стоит упомянуть:

* **архитектура разделена на слои** — запросы к базе отделены от логики,
  логика от обработки запросов;
* **миграции** — схема базы создаётся пошагово и версионируется;
* **свой SMTP-клиент** — около 500 строк на встроенных модулях Node.js,
  без сторонних библиотек;
* **всего три зависимости**: Express, better-sqlite3, dotenv.

## 6. Если что-то пошло не так

| Проблема | Что делать |
|---|---|
| `npm run demo` не запускается | проверь, что установлен Node.js версии 20 или выше: `node -v` |
| Порт 3000 занят | закрой другой сервер или перезагрузи компьютер |
| Письма не появляются в ящике | проверь, что http://127.0.0.1:8025 открывается, и что в `.env` указано `MAIL_TRANSPORT=smtp` |
| Письмо не пришло на реальную почту | это ожидаемо: ящик локальный. Для настоящей отправки нужен пароль приложения Gmail — см. README |
| Ссылка из письма не открывается | адрес ссылки — `http://127.0.0.1:3000`, он работает только на этом компьютере |
| Нужно начать заново | удали файл `data\pvh.db` и снова запусти `npm run demo` |

## Приложение. Если преподаватель просит отправить письмо на настоящую почту

Нужен пароль приложения Gmail (16 букв). Обычный пароль от почты
не подойдёт — Google отклоняет его для сторонних программ.

1. Открой [myaccount.google.com](https://myaccount.google.com) → *Безопасность*
2. Включи двухэтапную аутентификацию
3. Перейди в *Пароли приложений* и создай новый
4. В файле `.env` замени блок настроек почты:

```
MAIL_TRANSPORT=smtp
MAIL_FROM=erder101@gmail.com
SMTP_HOST=smtp.gmail.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=erder101@gmail.com
SMTP_PASSWORD=полученный_пароль_приложения
```

5. Перезапусти проект и проверь настройки:

```bash
npm run mail:check
```

Диагностика должна сообщить: **«Соединение установлено, вход выполнен»**.

После этого письма будут приходить на обычную почту.
