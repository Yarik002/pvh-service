# Как показать проект преподавателю (релиз v1.0)

Пошаговый план защиты: что запустить, что показать, что говорить.
Показ занимает 10–12 минут.

**Вход администратора:** логин `admin`, пароль `admin`.
Клиента регистрируешь сам на свою настоящую почту прямо во время показа.

> **Перед показом выключи VPN.** Письма уходят через Gmail, а VPN блокирует
> отправку почты. Проверить почту можно командой
> `docker compose exec app node scripts/check-mail.js` — должно быть
> «Соединение установлено, вход выполнен».

---

## 0. Подготовка (за 10 минут до показа)

1. Запусти Docker Desktop и дождись зелёного значка «Engine running».
2. Открой терминал в папке проекта и запусти приложение:

```bash
cd "C:\Users\USER\Desktop\Практика 2026\pvh-service"
docker compose up -d --build
```

3. Проверь, что всё поднялось: `docker compose ps` — контейнер `pvh-app`
   в состоянии `Up (healthy)`.
4. Открой в браузере две вкладки:
   * http://127.0.0.1:3000 — сайт;
   * свою почту (Gmail / Mail.ru), куда придут письма.
5. Подготовь вторую почту для второго клиента (не обязательно).

База уже чистая: в ней только администратор и 20 свободных ячеек.
Если перед показом ты что-то пробовал и хочешь снова чистую базу —
раздел 6 «Очистка базы».

---

## 1. Главная страница (1 минута)

Открой http://127.0.0.1:3000.

**Что говорить:**
«Это веб-приложение для пункта выдачи заказов. Сервер — Node.js и Express,
база данных — SQLite, интерфейс — HTML, CSS и JavaScript без фреймворков.
Справа — схема склада: 20 ячеек, она строится по реальным данным из базы.
Сейчас все ячейки свободны».

Покажи:
* переключатель темы (кнопка ◐ в шапке): светлая → тёмная → как в системе;
* сузь окно браузера (или открой с телефона) — меню сворачивается, таблицы
  превращаются в карточки.

---

## 2. Регистрация с подтверждением почты (2 минуты)

1. Нажми **«Создать учётную запись»**.
2. Заполни: имя, **свою настоящую почту**, пароль (например `Pvz2026!test`).
   Покажи индикатор надёжности пароля под полем.
3. Нажми «Зарегистрироваться» — появится сообщение, что письмо отправлено.

**Что говорить:** «Пароль хранится не в открытом виде, а как хеш scrypt
с солью. Пока адрес не подтверждён, войти нельзя».

4. Попробуй войти сразу — сайт скажет, что адрес не подтверждён, и предложит
   отправить письмо повторно.
5. Открой свою почту, найди письмо «Подтверждение адреса» и нажми кнопку
   в письме. Откроется страница «Адрес электронной почты подтверждён».
6. Войди со своей почтой и паролем.

---

## 3. Клиент: «Мои заказы» (1 минута)

После входа открой **«Мои заказы»** — список пока пуст, показано понятное
сообщение «Заказов пока нет».

**Оставь эту вкладку открытой** — на шаге 5 заказ появится в ней сам,
без перезагрузки страницы.

---

## 4. Администратор: приёмка посылки (2 минуты)

Открой **вторую вкладку в режиме инкогнито** (Ctrl+Shift+N) — там можно войти
вторым пользователем, не выходя из первого.

1. Войди: логин `admin`, пароль `admin`.
2. В меню — разделы администратора: «Все заказы», «Приёмка товара»,
   «Администрирование».
3. Открой **«Приёмка товара»**:
   * трек-номер: `RA123456789BY`;
   * получатель: начни вводить свою почту — появится подсказка;
   * описание: `Наушники`;
   * ячейка: «Автоматически — первая свободная».
4. Нажми **«Принять посылку»** — крупно покажется «№ 1».

**Что говорить:** «Заказ и занятие ячейки сохраняются в одной транзакции:
если что-то сломается посередине, не останется ни заказа без ячейки,
ни занятой ячейки без заказа. Клиенту ушло письмо с номером ячейки».

5. Прими ещё одну посылку, выбрав ячейку **вручную** (например № 7).

---

## 5. Клиент видит заказ без перезагрузки (1 минута)

Вернись на вкладку клиента. В течение 15 секунд:
* в таблице появятся оба заказа со статусом «Готов к выдаче»;
* сверху — чёрная плашка «В пункте выдачи вас ждут заказы» с номерами ячеек;
* всплывёт уведомление о новых заказах.

Открой свою почту — там письмо «Заказ RA123456789BY принят в пункт выдачи».

**Что говорить:** «Страница сама опрашивает сервер каждые 15 секунд (polling).
Если вкладка свёрнута, опрос ставится на паузу, чтобы не нагружать сервер».

Покажи фильтры: вкладки статусов со счётчиками, поиск по трек-номеру,
сортировку нажатием на заголовок столбца (стрелка меняет направление).

---

## 6. Администратор: выдача, изменение, удаление (2 минуты)

На вкладке администратора открой **«Все заказы»**.

1. У заказа в ячейке № 1 нажми **«Выдать»**. Откроется окно подтверждения
   с крупным номером ячейки и получателем. Нажми «Выдать заказ».
   Появится сообщение «Заказ выдан клиенту, ячейка № 1 свободна».
2. Нажми **«Изменить»** у второго заказа, поменяй описание, сохрани.
3. Нажми **«Ожидаемый заказ»** — зарегистрируй посылку, которая ещё в пути
   (статус «В пути», ячейки нет).
4. Открой **«Ячейки»** — ячейка № 1 снова свободна, № 7 занята; нажми на
   занятую — видно, чей заказ внутри.
5. Открой **«Администрирование»** — сводка: пользователи, ячейки, заказы
   по статусам.

На вкладке клиента статус первого заказа сам сменится на «Выдан».

**Что говорить:** «Выдача — тоже транзакция: статус «Выдан» и освобождение
ячейки выполняются вместе. Выданный заказ изменить нельзя — это история».

---

## 7. Профиль и удаление учётной записи (1 минута)

На вкладке клиента нажми на своё имя в шапке → **«Профиль»**:
* смени имя — оно сразу обновится в шапке;
* попробуй удалить учётную запись — сайт откажет, пока в ячейке лежит заказ
  («сначала заберите заказы»).

**Что говорить:** «Это бизнес-правило: нельзя удалить клиента, чья посылка
физически лежит на складе. Последнего администратора тоже удалить нельзя».

---

## 8. Ошибки и защита (1 минута)

* На странице «Мои заказы» останови сервер (`docker compose stop app`)
  и нажми вкладку «Выдан» — всплывёт понятное «Нет связи с сервером»,
  индикатор обновления станет красным. Затем `docker compose start app`.
* Клиент открывает http://127.0.0.1:3000/admin — страница «Доступ запрещён» (403).
* Гость открывает http://127.0.0.1:3000/orders — «Нужно войти в систему» с кнопкой входа.
* Несуществующий адрес http://127.0.0.1:3000/abc — оформленная страница 404.

## 10. Что показать в коде

| Что | Файл |
|---|---|
| Схема базы данных (3 таблицы, ограничения, триггер) | `src/db/migrations/001_initial_schema.sql` |
| Алгоритм назначения ячейки | `src/services/cellAssignment.js` |

| Автообновление статусов | `public/js/ordersLive.js` |

**Если спросят про структуру:** «Слоистая архитектура: маршруты (routes)
принимают запрос, сервисы (services) содержат бизнес-логику, репозитории
(repositories) работают с базой. Так каждую часть можно проверить отдельно».

## 11. Если что-то пошло не так

| Проблема | Что сделать |
|---|---|
| Письмо не пришло | Проверь «Спам». Выключи VPN. Команда проверки почты — в начале файла |
| Сайт не открывается | `docker compose ps`; если контейнера нет — `docker compose up -d` |
| «Docker Desktop is not running» | Запусти Docker Desktop, подожди 1–2 минуты |
| Нужно начать с чистой базы | раздел «Очистка базы» ниже |
| Забыл пароль клиента | Войди как admin и удали клиента в «Администрировании», зарегистрируй заново |

### Очистка базы

Удаляет всех клиентов и заказы, оставляет администратора admin / admin
и 20 ячеек:

```bash
docker compose stop app
docker compose run --rm app node scripts/clean-db.js
docker compose start app
```

Полностью новая база (если что-то совсем сломалось):

```powershell
docker compose down
Remove-Item data\pvh.db*
docker compose up -d
```

При запуске база создастся заново, с администратором admin / admin.

## Кратко: шпаргалка

1. `docker compose up -d --build` → http://127.0.0.1:3000
2. Регистрация на свою почту → письмо → подтверждение → вход.
3. Инкогнито: admin / admin → «Приёмка товара» → посылка на свою почту.
4. Вкладка клиента: заказ появился сам, письмо пришло.
5. «Все заказы» → «Выдать» → окно подтверждения → ячейка свободна.
6. Профиль, тёмная тема, телефонная ширина.
7. `docker compose exec app node scripts/run-tests.js` — 463 теста.
