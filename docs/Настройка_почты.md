# Настройка отправки почты на реальный адрес

## Проблема

В сети, где запускается проект, **протокол SMTP блокируется**: соединение
с почтовым сервером устанавливается, но сервер не отвечает. Проверено
на Gmail, Mail.ru и Яндекс.Почте — результат одинаковый.

Поэтому письма по умолчанию попадают в локальный ящик
(http://127.0.0.1:8025), а не на реальную почту.

## Решение: отправка через HTTPS-API

Почтовые сервисы принимают письма не только по SMTP, но и обычным
HTTPS-запросом. HTTPS в этой сети работает, поэтому такой способ
доставляет письма на настоящий адрес.

Поддерживаются два сервиса на выбор: **Resend** и **Brevo**.
Оба имеют бесплатный тариф, которого для учебного проекта достаточно.

---

## Вариант 1: Resend (проще всего)

1. Открой https://resend.com и зарегистрируйся (можно через GitHub или Google).
2. В личном кабинете открой раздел **API Keys** → **Create API Key**.
3. Скопируй ключ — он начинается с `re_`.
4. Открой файл `.env` в корне проекта и добавь:

```
MAIL_TRANSPORT=api
MAIL_API_PROVIDER=resend
MAIL_API_KEY=re_вставь_свой_ключ
MAIL_FROM=erder101@gmail.com
MAIL_MAILBOX_URL=
```

5. Проверь настройки:

```bash
npm run mail:check
```

Ожидаемый результат: **«Сервис доступен, ключ API принят»**.

> **Важно про адрес получателя.** На бесплатном тарифе без собственного
> домена Resend разрешает отправлять письма только на адрес, указанный
> при регистрации. Для показа этого достаточно: регистрируйся в приложении
> на свой же адрес — письмо придёт.

---

## Вариант 2: Brevo

1. Открой https://app.brevo.com и зарегистрируйся.
2. В разделе **Senders** добавь свой адрес электронной почты и подтверди его
   (придёт письмо со ссылкой).
3. В разделе **SMTP & API** → **API Keys** создай ключ и скопируй его.
4. Добавь в файл `.env`:

```
MAIL_TRANSPORT=api
MAIL_API_PROVIDER=brevo
MAIL_API_KEY=вставь_ключ
MAIL_FROM=erder101@gmail.com
MAIL_MAILBOX_URL=
```

5. Проверь: `npm run mail:check`

Brevo разрешает отправлять письма любым получателям с подтверждённого
адреса отправителя — ограничение в 300 писем в сутки.

---

## Запуск в Docker

Если проект работает в контейнерах, настройки передаются через файл
`.env.docker`. Добавь туда те же строки, что и в `.env`:

```
MAIL_TRANSPORT=api
MAIL_API_PROVIDER=resend
MAIL_API_KEY=re_вставь_свой_ключ
MAIL_FROM=erder101@gmail.com
MAIL_MAILBOX_URL=
```

Затем в `docker-compose.yml` раскомментируй две строки в сервисе `app`:

```yaml
    env_file:
      - .env.docker
```

И перезапусти:

```bash
docker compose down
docker compose up -d
docker compose exec app node scripts/check-mail.js
```

---

## Как вернуть локальный ящик

Если снова нужно проверять почту без интернета, верни настройки:

```
MAIL_TRANSPORT=smtp
SMTP_HOST=mailpit          # для Docker
SMTP_PORT=1025             # для Docker
SMTP_SECURE=false
MAIL_MAILBOX_URL=http://127.0.0.1:8025
```

Для запуска без Docker укажи `SMTP_HOST=127.0.0.1`.

---

## Кратко

| Режим | Настройка | Куда попадают письма |
|---|---|---|
| Локальный ящик | `MAIL_TRANSPORT=smtp` + `SMTP_HOST=mailpit` | http://127.0.0.1:8025 |
| Реальная почта через API | `MAIL_TRANSPORT=api` + ключ сервиса | настоящий адрес получателя |
| Только журнал | `MAIL_TRANSPORT=log` | консоль сервера |
