# Итоговая структура базы данных

**Проект:** веб-приложение «Сервис трекинга заказов и инвентаря для ПВЗ»
**СУБД:** SQLite 3
**Документ актуален для сборки:** v0.6.0

Настоящий документ описывает фактическую структуру базы данных проекта
после реализации 7-го дня практики. Он дополняет материалы 1-го дня
(ER-диаграммы в нотациях Баркера, Чена и Мартина), поскольку в ходе разработки
к первоначальным трём таблицам добавились служебные.

---

## 1. Состав таблиц

| Таблица | Назначение | Появилась |
|---|---|---|
| `Users` | пользователи системы (клиенты и администраторы) | 1-й день |
| `Storage_Cells` | ячейки хранения на складе пункта выдачи | 1-й день |
| `Orders` | заказы (посылки), связывающие пользователя и ячейку | 1-й день |
| `Sessions` | сессии авторизации | 7-й день |
| `schema_migrations` | служебная таблица учёта применённых миграций | 2-й день |

Схема создаётся миграциями в каталоге `src/db/migrations`:

| Файл миграции | Содержание |
|---|---|
| `001_initial_schema.sql` | таблицы `Users`, `Storage_Cells`, `Orders`, индексы, триггер, 20 ячеек |
| `002_users_password_fields.sql` | поля `password_changed_at`, `must_change_password` |
| `003_email_confirmation.sql` | поля `confirm_token_created_at`, `confirm_attempts` |
| `004_sessions.sql` | таблица `Sessions` |

## 2. Таблица Users

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | идентификатор |
| `name` | TEXT | NOT NULL, длина 2–100 символов | имя пользователя |
| `email` | TEXT | NOT NULL, UNIQUE, COLLATE NOCASE, формат адреса | адрес электронной почты (логин) |
| `password_hash` | TEXT | NOT NULL | хеш пароля (scrypt со случайной солью) |
| `role` | TEXT | NOT NULL, `client` или `admin` | роль пользователя |
| `is_confirmed` | INTEGER | NOT NULL, 0 или 1 | признак подтверждения адреса почты |
| `confirm_token` | TEXT | UNIQUE | текущий токен подтверждения |
| `password_changed_at` | TEXT | — | дата последней смены пароля |
| `must_change_password` | INTEGER | NOT NULL, 0 или 1 | требование сменить пароль |
| `confirm_token_created_at` | TEXT | — | дата формирования токена подтверждения |
| `confirm_attempts` | INTEGER | NOT NULL, ≥ 0 | число неудачных попыток подтверждения |

**Ключевые ограничения целостности:**

* `email` объявлен с `COLLATE NOCASE` — регистр адреса не влияет на поиск
  и проверку уникальности, поэтому повторная регистрация на тот же адрес
  в другом регистре невозможна;
* роль ограничена значениями `client` и `admin` — исключены произвольные роли;
* признак подтверждения и требование смены пароля принимают только 0 или 1;
* `confirm_token` уникален — два пользователя не могут получить один токен.

## 3. Таблица Storage_Cells

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | идентификатор |
| `cell_number` | INTEGER | NOT NULL, UNIQUE, > 0 | номер ячейки |
| `status` | TEXT | NOT NULL, `Свободна` или `Занята` | состояние ячейки |

При создании базы данных автоматически добавляются 20 ячеек хранения.

---

## 4. Таблица Orders

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | идентификатор |
| `track_number` | TEXT | NOT NULL, UNIQUE | трек-номер посылки |
| `description` | TEXT | — | описание посылки |
| `user_id` | INTEGER | NOT NULL, внешний ключ на `Users` | получатель |
| `cell_id` | INTEGER | внешний ключ на `Storage_Cells` | ячейка хранения |
| `status` | TEXT | NOT NULL, `В пути` / `Готов к выдаче` / `Выдан` | статус заказа |
| `received_at` | TEXT | — | дата поступления |
| `issued_at` | TEXT | — | дата выдачи |

**Правила ссылочной целостности:**

* `user_id` → `Users(id)`: `ON DELETE CASCADE` — при удалении пользователя
  удаляются его заказы;
* `cell_id` → `Storage_Cells(id)`: `ON DELETE RESTRICT` — ячейку нельзя удалить,
  пока на неё ссылается заказ.

**Логические ограничения (`CHECK`):**

* дата выдачи заполнена тогда и только тогда, когда заказ выдан;
* заказ в статусе «Готов к выдаче» обязан иметь ячейку и дату поступления.

**Индексы и триггер:**

* четыре индекса для ускорения выборок: по пользователю, ячейке, статусу
  и дате поступления;
* частичный уникальный индекс `ux_orders_active_cell` гарантирует, что одна
  ячейка обслуживает не более одного активного заказа;
* триггер `trg_orders_free_cell_on_delete` освобождает ячейку при удалении
  невыданного заказа.

## 5. Таблица Sessions

| Поле | Тип | Ограничения | Назначение |
|---|---|---|---|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | идентификатор сессии |
| `token_hash` | TEXT | NOT NULL, UNIQUE | хеш токена сессии (SHA-256) |
| `user_id` | INTEGER | NOT NULL, внешний ключ на `Users` | владелец сессии |
| `created_at` | TEXT | NOT NULL | дата создания |
| `expires_at` | TEXT | NOT NULL | дата окончания |
| `last_used_at` | TEXT | — | дата последнего обращения |
| `user_agent` | TEXT | — | сведения о браузере клиента |
| `ip_address` | TEXT | — | адрес клиента |

**Особенности реализации:**

* в базе данных хранится **хеш** токена, а не сам токен: утечка базы данных
  не позволяет воспользоваться чужой сессией;
* `user_id` → `Users(id)` с `ON DELETE CASCADE`: при удалении пользователя
  его сессии удаляются автоматически;
* истёкшие сессии не возвращаются при проверке (условие в запросе),
  а также удаляются отдельной командой очистки;
* два индекса: по пользователю и по дате окончания.

---

## 6. Связи между таблицами

```
Users ──1:N──> Orders ──N:1──> Storage_Cells
  │
  └──1:N──> Sessions
```

| Связь | Тип | Правило удаления |
|---|---|---|
| `Users` → `Orders` | один ко многим | CASCADE |
| `Users` → `Sessions` | один ко многим | CASCADE |
| `Storage_Cells` → `Orders` | один ко многим | RESTRICT |

Пояснение по связи «ячейка — заказы»: одна ячейка связана с заказами,
занимавшими её в разные периоды времени. Одновременно ячейку может занимать
только один активный заказ — это обеспечивается частичным уникальным индексом.

---

## 7. Хранение паролей и токенов

| Данные | Как хранятся |
|---|---|
| Пароль | хеш `scrypt` со случайной солью 16 байт, формат `scrypt$N$r$p$соль$хеш` |
| Токен подтверждения адреса | в открытом виде (это одноразовая ссылка ограниченного срока действия) |
| Токен сессии | только хеш SHA-256 |

Пароль в открытом виде не сохраняется ни в базе данных, ни в журналах работы
сервера.
