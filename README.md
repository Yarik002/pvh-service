# Сервис трекинга заказов и инвентаря для ПВЗ

Веб-приложение для учёта заказов и автоматизации работы пункта выдачи заказов (ПВЗ).

## 1. Назначение проекта

Приложение предназначено для автоматизации процессов приёмки, адресного хранения
и выдачи заказов в пункте выдачи заказов, а также для предоставления клиентам
возможности самостоятельно отслеживать статусы своих посылок.

Основные возможности (по техническому заданию):

* регистрация и авторизация пользователей с подтверждением Email;
* разграничение прав доступа по ролям `client` / `admin`;
* приёмка заказов с автоматическим или ручным назначением ячейки хранения;
* выдача заказов с освобождением ячейки;
* просмотр, фильтрация и сортировка списков заказов;
* адаптивная вёрстка и переключение светлой/тёмной темы.

## 2. Состояние разработки

Разработка ведётся итеративно, по дням практики. Реализовано на текущий момент:

| День | Работа | Состояние |
|---|---|---|
| 1 | Проектирование базы данных, SQL-скрипт (таблицы `Users`, `Orders`, `Storage_Cells`) | выполнено |
| 2 | Репозиторий, окружение, каркас сервера, подключение SQLite, **сборка v0.1** | выполнено |
| 3 | API регистрации пользователей с валидацией полей и формата Email, **сборка v0.2** | выполнено |
| 4–25 | Хеширование паролей, Email-подтверждение, авторизация, вёрстка, CRUD, тесты, релиз v1.0 | план |

**Достигнутые критерии приёмки:**

* 2-й день — сервер запускается, эндпоинт `/health` возвращает OK;
* 3-й день — работающий API регистрации, проверенный в Postman
  (коллекция `docs/postman/PVZ-Auth-Day3.postman_collection.json`).

## 3. Технологический стек

| Компонент | Технология | Обоснование |
|---|---|---|
| Среда выполнения | Node.js 20+ (проверено на 24.21.0) | единый язык JavaScript на клиенте и сервере |
| Веб-фреймворк | Express 4 | минималистичный, стандарт де-факто для REST API |
| СУБД | SQLite 3 (библиотека `better-sqlite3`) | требование ТЗ, п. 3.7; не требует установки сервера БД |
| Конфигурация | `dotenv` | настройки вынесены из кода в файл `.env` |
| Тестирование | встроенный модуль `node:test` | не требует дополнительных зависимостей |
| Пакетный менеджер | pnpm (совместим с npm) | быстрая установка, воспроизводимость через lock-файл |

Клиентская часть — адаптивная вёрстка на HTML5/CSS3 с JavaScript (без тяжёлых
фреймворков), разрабатывается с 9-го дня практики.

## 5. Установка и запуск

### 5.1 Требования

* Node.js версии 20 или выше;
* npm или pnpm.

### 5.2 Порядок установки

```bash
# 1. Перейти в каталог проекта
cd pvh-service

# 2. Установить зависимости (любой из двух вариантов)
npm install
pnpm install

# 3. Выполнить первоначальную настройку: создать файл .env,
#    базу данных, применить миграции и проверить сборку
npm run setup
```

Команда `npm run setup` выполняет все необходимые действия автоматически:
проверяет версию Node.js, создаёт файл `.env` из образца `.env.example`,
проверяет наличие зависимостей, создаёт базу данных, применяет миграции
и запускает контрольную проверку сборки.

Если настройка выполняется вручную, создайте файл настроек:

```bash
copy .env.example .env      # Windows
cp .env.example .env        # Linux / macOS
```

### 5.3 Запуск сервера

```bash
npm start          # обычный запуск
npm run dev        # запуск с автоматической перезагрузкой при изменении кода
```

После запуска в консоль выводится адрес сервера:

```
Сервер запущен: http://127.0.0.1:3000
Проверка работоспособности: http://127.0.0.1:3000/health
```

### 5.4 Проверка работоспособности

```bash
npm run check      # автоматическая проверка сборки v0.2 (22 проверки)
npm test           # все модульные тесты (4 файла)
```

Ожидаемый результат проверки:

```
Всего проверок: 22, пройдено: 22, ошибок: 0
РЕЗУЛЬТАТ: сборка v0.2.0 соответствует критерию приёмки — API регистрации работает, проверки пройдены.
```

Сценарий `check-v0.1.js` (проверка 2-го дня) сохранён и запускается командой
`npm run check:v01`.

### 6.2 Регистрация пользователя

**`POST /api/auth/register`** — создание учётной записи с ролью `client`.

Тело запроса (JSON):

```json
{
  "name": "Иванов Иван",
  "email": "ivanov@mail.ru",
  "password": "parol12345",
  "passwordConfirm": "parol12345"
}
```

Правила проверки полей:

| Поле | Обязательное | Правила |
|---|---|---|
| `name` | да | от 2 до 100 символов, крайние пробелы удаляются |
| `email` | да | корректный формат, не более 254 символов, приводится к нижнему регистру, должен быть уникальным |
| `password` | да | от 8 до 128 символов, минимум одна буква и одна цифра |
| `passwordConfirm` | да | должен совпадать с `password` |

Ответы:

| Статус | Когда возвращается |
|---|---|
| `201 Created` | пользователь создан |
| `400 Bad Request` | поля заполнены неверно; `error.details` содержит ошибку по каждому полю |
| `409 Conflict` | адрес электронной почты уже зарегистрирован |
| `429 Too Many Requests` | превышено число попыток (защита от перебора) |

Пример успешного ответа:

```json
{
  "success": true,
  "message": "Регистрация выполнена успешно. Подтвердите адрес электронной почты.",
  "user": {
    "id": 1,
    "name": "Иванов Иван",
    "email": "ivanov@mail.ru",
    "role": "client",
    "isConfirmed": false
  },
  "nextStep": "На адрес электронной почты будет отправлена ссылка для подтверждения аккаунта."
}
```

Пример ответа при ошибке валидации:

```json
{
  "success": false,
  "error": {
    "code": "BAD_REQUEST",
    "message": "Укажите корректный адрес электронной почты, например ivanov@mail.ru",
    "details": {
      "email": {
        "code": "BAD_FORMAT",
        "message": "Укажите корректный адрес электронной почты, например ivanov@mail.ru"
      }
    }
  }
}
```

### 6.3 Проверка API в Postman

В каталоге `docs/postman/` находятся готовая коллекция и окружение:

| Файл | Назначение |
|---|---|
| `PVZ-Auth-Day3.postman_collection.json` | 7 запросов с автоматическими проверками ответов |
| `PVZ-local.postman_environment.json` | окружение с адресом сервера и тестовыми данными |

Порядок работы:

1. Запустить сервер: `npm start`.
2. В Postman импортировать оба файла (*File → Import*).
3. Выбрать окружение «ПВЗ — локальный сервер».
4. Выполнить запросы по порядку. Каждый запрос содержит вкладку *Tests*
   с проверками — результаты отображаются на вкладке *Test Results*.

```json
{
  "success": true,
  "status": "OK",
  "message": "Сервер работает, база данных доступна",
  "application": "Сервис трекинга заказов и инвентаря для ПВЗ",
```

## 7. База данных

Схема создаётся автоматически при первом запуске сервера из файла миграции
`src/db/migrations/001_initial_schema.sql`.

| Таблица | Назначение | Ключевые ограничения |
|---|---|---|
| `Users` | пользователи системы | уникальный Email, роль `client`/`admin`, признак подтверждения |
| `Storage_Cells` | ячейки хранения | уникальный номер, статус «Свободна»/«Занята» |
| `Orders` | заказы (посылки) | уникальный трек-номер, статус, внешние ключи на пользователя и ячейку |

Реализованные ограничения целостности:

* внешние ключи с правилами `ON DELETE CASCADE` (пользователь → заказы)
  и `ON DELETE RESTRICT` (ячейка → заказы);
* `CHECK`-условия на формат Email, длину имени, допустимые значения ролей и статусов;
* согласованность статуса и даты выдачи заказа;
* частичный уникальный индекс `ux_orders_active_cell` — одна ячейка обслуживает
  не более одного активного заказа;
* триггер `trg_orders_free_cell_on_delete` — освобождение ячейки при удалении заказа.

При создании базы данных автоматически добавляются 20 ячеек хранения.

Управление схемой:

```bash
npm run db:migrate           # применить новые миграции
node scripts/migrate.js status   # показать состояние миграций
npm run db:reset             # пересоздать базу данных (с подтверждением)
```

## 8. Настройки (файл `.env`)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | порт HTTP-сервера |
| `HOST` | `127.0.0.1` | интерфейс прослушивания |
| `NODE_ENV` | `development` | режим работы |
| `DB_FILE` | `./data/pvh.db` | путь к файлу базы данных |
| `DB_VERBOSE` | `false` | вывод SQL-запросов в консоль |
| `DB_AUTO_MIGRATE` | `true` | автоматическое применение миграций при старте |
| `LOG_LEVEL` | `info` | уровень подробности журнала |
| `RATE_LIMIT_WINDOW_MS` | `900000` | длительность окна ограничения частоты запросов (15 минут) |
| `RATE_LIMIT_MAX` | `20` | предельное число попыток регистрации за окно с одного IP |

Файл `.env` не добавляется в репозиторий: он содержит локальные настройки.
Актуальный образец настроек всегда хранится в `.env.example`.
